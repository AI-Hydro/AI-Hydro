## How it works

By default, AI-Hydro will ask for your permission before calling any tool, including reading or writing files.

If you want to allow AI-Hydro to do something without asking, you can set the Auto Approve permission for that tool.

## Permission Options

-   **Read project files**

    -   Allows AI-Hydro to read files within your current workspace without asking
    -   **Read all files**
        -   Extends read permission to files outside your workspace (system files, config files, etc.)

-   **Edit project files**

    -   Allows AI-Hydro to modify files within your current workspace without confirmation
    -   **Edit all files**
        -   Extends modification permission to files outside your workspace

-   **Run read-only commands**

    -   Runs a command without asking only when AI-Hydro itself classifies it as read-only: a short allowlist of programs and subcommands (`ls`, `cat`, `grep`, `git status`, and similar), optionally piped into other read-only commands. The model's own claim that a command is safe is not used; it can only make a command ask more, never less.
    -   Anything outside the allowlist asks: unknown programs, `;` / `&&` / `||`, redirection, `$(...)` and backticks, here-docs, scripts such as `python -c` or `sh -c`, `curl`, installs, and anything that mentions protected paths.
    -   This is a conservative filter, not a sandbox.
    -   Read-only `git` commands auto-run only in a trusted workspace, because a repository's own git config can make git run programs; workspace trust is the real protection against a hostile repository's git config (the environment hardening AI-Hydro adds is only a second layer and cannot cover every config key).
    -   **Run any command**
        -   Permits execution of any terminal command without asking. The exceptions below still apply.

-   **Always blocked or asked, whatever the settings (including YOLO)**

    -   Claim approval is never run by the agent. A command that mentions `aihydro-approve` or `ai_hydro.approval` is refused; run claim approval yourself in your own terminal. This is a text match and cannot catch indirection (a variable that builds the name, a script file, an encoded payload). The approval CLI additionally refuses to run in a terminal the extension marked as agent-run (`AIHYDRO_AGENT_CONTEXT`). A process running as your own user can still bypass both; only a touch-required (`sk-`) signature stops that.
    -   Running a program named `aihydro` (the retired command-line subagent) is always refused, in every setting including YOLO mode. Paths and names that merely contain "aihydro" are not affected.
    -   File edits, and commands that mention the MCP settings file, the extension storage directory, `$AIHYDRO_HOME/{approvals,trust,registry}` or `~/.ssh` always ask, even with "Edit" auto-approve on.
    -   Edits to the MCP settings file made outside the AI-Hydro UI that would let tools run without asking (a new `autoApprove` entry, trust turned on, a `deny`/`alwaysAsk` entry removed) are applied only after you confirm them.

-   **Browse websites**

    -   Allows AI-Hydro to use the browser tool to fetch web content

-   **Use MCP servers**

    -   Permits connection to and usage of MCP servers for extended functionality

-   **Maximum requests**
    -   Sets the number of consecutive automated actions AI-Hydro can take before requiring your input

## Best Practices

Personally, I like to keep auto-editing disabled because it gives me a chance to review changes every step of the way.

For most serious development workflows, I recommend starting with:

-   Auto-approving read access to project files
-   Setting a reasonable maximum request limit (10-20)

This gives AI-Hydro enough freedom to explore your codebase without constant interruptions, while still requiring permission for edits or potentially destructive actions.

As you build more trust in AI-Hydro's capabilities with your specific projects, you can gradually increase the permissions to match your comfort level.

Remember that you can always adjust these settings as your needs change - tighten permissions for critical production work, or loosen them when prototyping and exploring.

You can even use the quick "star" actions to quickly toggle your auto-approved selections on and off as you go.
